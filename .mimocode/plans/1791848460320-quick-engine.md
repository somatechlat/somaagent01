## P0 — FIX BROKEN AGENT NOW (LLM auth)

**Symptom:** `LLMNonRetryableError: Incorrect API key provided: tp-s23ap…` for `openai/mimo-v2.6-flash`.

**Root cause (code-truth):**
- `admin/llm/providers.py:115-123` — `provider_requires_api_key("mimo")` is **True** (mimo not in `GATEWAY_KEYED_PROVIDER_IDS`)
- LiteLLM addresses mimo as `openai/<model>` (`providers.py:126-137`)
- A non-OpenAI key (`tp-…`) is sent to OpenAI's API → reject

**Fix (real, no bypass):**
1. Decide key policy for `mimo` (gateway-keyed like custom/ollama **or** Vault `secret/agent/api_keys/mimo_api_key`)
2. Align `GATEWAY_KEYED_PROVIDER_IDS` / `get_api_key` / `provider_requires_api_key` docstrings (`litellm_helpers.py:144-167` vs `providers.py:115-123` contradict each other)
3. Ensure `api_base` is the MiMo deployment URL (not `api.openai.com`) when model is `openai/mimo-v2.6-flash`
4. Fail-closed with a clear `LLMNotConfiguredError` naming the Vault path — never fall back to a random OpenAI key
5. Round-trip: live `POST /chat` or model ping returns 200 with the real model
6. Unit test: mimo call never injects `OPENAI_API_KEY`; wrong-key path returns honest error

**Verify:** live chat reply (not mock) + `admin/llm` tests green.
